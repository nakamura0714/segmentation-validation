## 作業内容

### 1. シンボリックリンクの作成

```bash
ln -s /mnt/medicaldb/annotation/datasets/engineer-set-ANN_EIRLPRJ_01263-20260916_032022.json \
      /mnt/project/chest/metry/pi6/dataset/source/engineer-set-ANN_EIRLPRJ_01263-20260916_032022.json
```

既存12本と同じ形式（絶対パスの symlink、リンク名は実体と同名）に揃える。
`dataset/source/` はリポジトリ外（`/mnt/project/chest/metry/pi6/dataset/source/`）で git 管理対象ではないため、
コミットは発生しない。

設定変更は不要。[config.py:32](src/segmentation_validation/config.py#L32) の
`DatasetsConfig.sources` が既定で `../../../dataset/source/*.json` という glob であり、
[README.md:1271-1275](README.md#L1271-L1275) にも「リンクするだけで次回 scan から自動的に対象へ入る」と明記されている。

### 2. 確認

```bash
ls -la /mnt/project/chest/metry/pi6/dataset/source/          # 13本、リンク先が解決できるか
uv run segmentation-validation list-sources                   # 13本として認識されるか
```

`list-sources` が 01263 を含む13本を出せば完了。
`Config.dataset_sources()` → `_expand_glob()`（[config.py:374](src/segmentation_validation/config.py#L374) 付近）が拾う。

## 今回はやらないこと（次のタイミングで実施）

リンクを張った時点で `core/cache.py::fingerprint(config)` が変わり、
`output/validation/<fingerprint>/` 配下のキャッシュ・出力は空になる。
本実行は `docs/review_procedure.md` の「5.3 fingerprint が変わったとき」に従う:

```
scan --jobs 8  →  check  →  review build / launch / export  →  select  →  report  →  build-dataset
```

- `--set` は全コマンドで同一に揃えること（1つ違うと別 fingerprint の別ディレクトリに書かれる）。
- 過去の目視結果の引き継ぎ作業は不要。正本の `review/review_decisions.json` は fingerprint 非依存で、
  突合キーが `dataset_id::geometry_uid`、`dataset_id` は
  `adapters/engineer_set.py::dataset_id_for()` がファイル名末尾の `-YYYYMMDD_HHMMSS` を落とすため不変。
  `review_policy/image_decision_overrides.json` も同様に引き継がれる。
- `scan` を飛ばすと画素が必要な14チェックが黙って「検出なし」になり、`select` が止まる。
- `serve` を常駐させている場合は fingerprint に追従させる。

### 重複17画像の扱い（決定済み: 現行ロジックのまま）

`selection/build_dataset.py::resolve_image_duplicates` / `_pick_winner` は
①keep annotation の有無 → ②**元JSON生成日時が新しい方** → ③`dataset_id` 昇順 の順で勝者を選ぶ。
01263（2026-09-16）は既存の `ETR_ChestMetry_PI6px_abnormal_non_pneumothorax`（2026-09-07）等より新しいため、
重複17画像は 01263 側が採用され、既存の `Grade` / `Location` / `Disease` 付きアノテーションは
統合JSONから落ちる。**この挙動を変更せず受け入れる**（今回はコード変更なし）。

annotation レベルの D05（`checks/duplicate/d05_cross_dataset_duplicate.py`）は
`mask_hash` / `json_bbox` とラベルの一致で重複判定するため、MD5もラベルも不一致な今回のケースは
重複と判定しない。ただし同一 `geometry_uid` が無いことは確認済みなので
`D05_CROSS_DATASET_MISMATCH`（要目視の CRITICAL）も発生しない見込み。
実際の結果は次回 `check` 実行時に `output/development/<version>/image_duplicates.csv` と
D05 のレポートで確認する。
