読み方

      
数字の意味を後から思い出せなくならないように。

    

    

      
症例の階層

        患者 → study（1回の検査） → series → 画像 → annotation の入れ子。
        1患者が複数の study を持つ例が実在する（51患者が2件以上、最大5件）ので患者と study は別に数える。
        1画像に複数の annotation があるため、annotation 数は目視で開く枚数ではない。
        なお file_list の総数 1083 に対し annotation を持つのは 863画像で、
        残り 220画像は annotation ゼロ。

      
auto: / review: タグ

        FiftyOne 上で機械は auto: タグしか付けず、人間は
        review: タグと review_* フィールドしか触らない。
        再構築のたびに auto: は貼り直され、人間の判定は保持される。
        この分離のおかげで自動ルールの Precision を後から計算できる。
        annotation の判定は Label（Detection）に、画像の判定は Sample に持たせる ——
        1枚に複数 annotation があるので、Sample タグに付けるとどれがダメだったのか分からなくなる。

      
Issue
「怪しい」と検出された候補。1つの annotation が複数持つことがある（全1144件）。Issue があること自体は除外を意味しない。微小領域として検出されても、目視で妥当なら keep になる。検出の記録は消えないので、後から自動ルールの Precision を計算できる。

      
SelectionDecision
最終的な採否。selection_decisions.csv が採否の唯一の正本で、build-dataset はこれだけを見る。全 annotation が必ず1行ある（1817行）。Issue が1つも出なかった正常な annotation も keep として1行出る。

      
keep
開発データに使う。

      
exclude
使わない。現在は全て D01（完全一致の重複）の古い方。

      
pending
まだ人が見ていない。目視待ち。pending = 0 が目視完了の条件。

      
uncertain
見たが判断できなかった（要相談・保留）。現在0件。

      
no_issue_detected
全チェックが実行され、問題が見つからなかった（984件）。

      
kept_without_full_check
一部のチェックが実行できないまま keep した（481件）。「検査して問題なかった」のではなく「検査できなかった」。体外判定に必要な胸郭マスクが約3割のファイルで未整備なため。黙って keep にすると「問題なし」と「未検査」が区別できなくなるので、別の理由として記録している。

      
older_exact_duplicate
画素が完全一致しラベルも同じ重複のうち、timestamp が古い方（101件）。「完全一致なのでどちらでも学習上の影響はない。日付が新しい方を使うのが自然」との確認に基づく自動判定。

      
unverified_checks
その annotation について検査できなかった check_id。現在509件が非空。用途は2つ：「検査して問題なし」と「検査できていない」を区別する／後から目視対象に加えるときの絞り込みキーになる（設定 cannot_determine_as_review_required を true にすると、ちょうどこの集合が目視キューに入る）。

      
path_mask
修正後。開発データとして使うもの。brush 全1665件に存在し、mode=L・画素値 0/255 の例外なし。

      
path_original_mask
Annotation Tool が作成した修正前。1568件（94%）が持つので存在自体は異常ではない。RGBA 1462件（ブラシのアンチエイリアスが alpha に入る）+ L 106件。path_mask と同じ条件で検査してはいけない — 実際に同一視すると1400件超のノイズが出て本物の検出が埋まる。S04 は「輪郭を穴埋めした結果が path_mask と食い違うもの」だけを拾う。

      
reference mask
体外領域判定で「どこまでが体内か」を決める、別パイプラインの生成物。lung / thorax / mediastinum の3種。PI6 の thorax-mask は塗りつぶし領域ではなく胸壁内縁をなぞる2本の細い曲線（前景1.26%）で、そのまま包含率を計算すると中央値 0.0295 になり正常なマスクまで全件が「体外」になる。lung 単独も使えない（胸水・気胸は定義上、含気肺野の外。実測で胸水131件中111件が包含率0.5未満）。そこで3種から領域を組み直し、行方向の範囲を上下へ外挿した「側方バンド」を作る。垂直方向は罰しないので肺尖への伸展や肋横角の胸水は許容し、胸壁より外側 = 上腕・肩へのはみ出しだけを拾う。

      
cannot_determine
検査できなかった状態。keep にはするが unverified_checks に記録する。内訳は no_reference 500 / lung_only 8 / reference_corrupt 1（21バイトの Internal Server Error というテキストファイルが混ざっている）。lung_only で lung ベースにフォールバックはしない — 気胸は原理的に肺野の外にあるので意味を持たないため。
